# Security checklist: ASVS L2 and MASVS

Where each control is enforced and where it is tested, with the gaps stated plainly. Targets: OWASP ASVS 5.0 Level 2 (web, API) and OWASP MASVS (mobile). Specs: [backend](../specs/backend-spec.md#security), [web](../specs/web-spec.md#security), [mobile](../specs/mobile-spec.md#security).

Status: **Done** (enforced and tested), **Partial** (enforced, test or scope incomplete), **Gap** (not done; see the list at the end). Paths are relative to the repository root.

## Gaps and accepted risks

1. **`style-src-attr 'unsafe-inline'`** in the web CSP. `next/image` and Radix emit `style="..."` into server HTML, which a nonce cannot cover. Scripts and `<style>` elements stay nonce-only. Removing it means replacing `next/image` and Radix hidden inputs.
2. **Media processing covers images only.** Images are re-encoded by the `media` job (sharp). **PDFs are validated by magic bytes and stored as uploaded** (no sanitising; they are served as downloads from a private prefix). **Videos are not probed or transcoded**: the size and type limits apply, but the 60 s duration and codec checks of the spec need `ffprobe` in the worker image (TODO). **HEIC is refused** with a clear message, because sharp's prebuilt libheif has no HEVC decoder. The passthrough processor is refused in staging and production.
3. **Mobile resilience:** no certificate pinning, root detection or tamper checks. Pinning to a CDN-fronted API risks lockouts on certificate rotation; decide with payments. The Android CI build (`build-apk.yml`) publishes a **debug** APK to a GitHub Release on every `main` push: fine for internal testing, but a debuggable build must not be what customers install; restrict or remove before launch.
4. **`TRUST_PROXY` is not validated** against the deployment. A wrong value breaks per-IP limits (0 behind the proxy) or lets clients spoof `X-Forwarded-For` (too high).
5. **Payments and webhooks** are not built, so signature checks, replay tolerance and payout controls are unreviewed.
6. **Open advisories** (`pnpm audit`): 5 moderate and 2 low, all in dev or build tooling (`glob` via testcontainers, `minimatch` via eslint, `node-forge` and `deepmerge` via `@expo/cli` and jest). None is in a runtime bundle. CI fails on high or critical.
7. **Account lockout can be abused** to lock a known account for 15 minutes; needs a product decision (step-up instead of hard lock).
8. **No DAST result yet**: the ZAP baseline workflow exists and is manual ([dast.md](dast.md)); run it before launch.
9. **Observability:** no alerting on auth failures, CSP reports (only a log line until Sentry is wired), or admin reads.
